## Dependency notes

- **004 requires 001** because it extends the URL validation path that 001
  consolidates into a single shared `urlValidator`. Running 004 first would add
  the Safe Browsing check to `/add` only, leaving `/edit` both scheme-unchecked
  and reputation-unchecked.
- **005 requires 003** because it adds the blocklist refresh to the `scheduled`
  handler that 003 introduces. Without 003 there is no cron handler to extend.
- **006 requires 003** only for ordering sanity: both touch the `domain` value's
  producer and consumer. 003 moves the purge (the consumer) into its own file
  first, so 006's change to the producer is reviewed against a stable consumer.
- **001, 002, 003, 007, 008 are mutually independent** and can run in parallel.
- 004 and 005 both insert a check into `/add`. If run concurrently they will
  conflict in the same region of `src/handlers/add.ts`; run them sequentially.
  Intended final order in that handler: blocklist (local, instant) before
  Safe Browsing (network, ~2s timeout).

## Context every executor needs

- **No test suite exists.** There is no test runner, no test files, and no `test`
  script in `package.json`. Every plan verifies by typecheck, lint, and a manual
  smoke test against a local `wrangler dev`. No plan should add a test framework.
- **Never run `wrangler` commands with `--remote`.** The production database
  holds 128 real links. All plans use `--local`, which only touches
  `.wrangler/state`.
- `Env` is an ambient global type generated into `worker-configuration.d.ts` by
  `bun run types`. It is never imported. Re-run `bun run types` after any
  `wrangler.toml` binding change.
- Zod is v4: `z.url()` and `z.uuid()`, not `z.string().url()`.
- `bunfig.toml` enforces a 3-day minimum release age on new dependencies. A
  refused install is the guard working as intended — never disable it.

## Findings considered and rejected

- **Phishing.Database as a blocklist source**: 391,959 entries, MIT licensed, but
  it lists `pastebin.com`, which an existing production link uses. Adding it
  would break that link and require an override mechanism. Rejected in favor of
  hagezi TIF mini (183,052 entries, zero false positives against current live
  data).
- **Spamhaus DBL / SURBL / URIBL**: their free public DNS mirrors refuse queries
  from datacenter IPs and public resolvers, returning sentinel values instead of
  answers. Cloudflare Workers can only query via DoH from Cloudflare IPs, so
  these are unusable without a paid Data Query Service subscription.
- **OpenPhish free feed**: terms restrict it to personal/academic research; a
  public community service is not covered.
- **URLhaus**: URL-level rather than domain-level, requiring different matching
  logic for marginal additional coverage at this project's volume.
- **Checking the blocklist or Safe Browsing at redirect time**: would put a
  third-party call or a large KV read in the hot path of every redirect. The
  write path is the right place to enforce.
- **Backfilling the `domain` column** (plan 006): all 18 existing distinct domain
  values are already correct simple two-label domains, so recomputation is a
  no-op.
- **`Strict-Transport-Security` header** (plan 008): Cloudflare manages HSTS at
  the zone level; setting it per-asset would not cover Worker responses.

## Known gaps not covered by any plan

Recorded so they are not mistaken for oversights:

- **`/edit` has no reputation check.** Plan 001 closes the scheme hole there, but
  a link can still be created clean and edited to a domain that Safe Browsing or
  the blocklist would reject. Extending 004/005 to `/edit` is the natural
  follow-up and would reuse `checkUrl`/`isBlocked` unchanged.
- **Existing stored URLs are never re-screened.** Links created before the
  blocklist existed are not audited against it.
- **`SALT` is not set on the deployed Worker** as of this writing. Edit secrets
  cannot validate until `wrangler secret put SALT` is run with the original
  value from the former Pages project.
